# Sitenalyzer

## Site brief design preview

[Back to project README](../README.md)

The [interactive preview](../mockups/site-brief/index.html) shows a proposed interface for Sitenalyzer.
It uses synthetic sites and people. It does not connect to SharePoint or change the deployed app.
Use it to review navigation, wording, layout, and print coverage before implementation.
For the design decisions and implementation requirements, start with the [UI redesign handoff](ui-redesign.md).

### Open the preview

Open `mockups/site-brief/index.html` in a current desktop browser.
Keep the preview inside this repository so the existing spreadsheet library can load.
No build, installation, sign-in, or configuration is needed to explore it.

For a local browser address, run `node mockups/site-brief/serve.cjs` from the repository root.
Open the address printed by the command. The server listens only on this computer
and serves an allowlist of preview files, review artifacts, and the existing spreadsheet library.
It does not expose the rest of the repository.

Select **Explore every screen** for links to the main views and alternative states.
The [screen gallery](../mockups/site-brief/review/index.html) contains captured views.
The [sample PDF](../mockups/site-brief/review/synthetic-full-site-report.pdf) shows the full printed report.
Both are generated by the verification command below.
Each gallery link reopens its example site, search, expanded details, dialog, worksheet,
or description editor in a fresh browser session. Links never save edits or start downloads.
Window size and forced-color preferences still follow your browser settings.

### Available views

| Area | What you can review |
| --- | --- |
| Overview | Queried site logo, editable description, address, counted permission shortcuts, library and list summaries. |
| Change site | Search for an example site or enter its exact example address. |
| Contents | Library, list, and page browsing with an adjacent detail panel. |
| Library details | Overview, folders, columns, permissions, technical details, and settings actions. |
| List details | Overview, columns, permissions, descriptions, calculated columns, and internal names. |
| Permissions | Guest and organization-wide access summary, separate-permission and missing-description findings, site permissions, people and groups, individual access, sharing links, and app access. |
| Site page details | A synthetic thumbnail, plus examples where a thumbnail is missing or cannot load. |
| Site review | Cleanup findings, missing descriptions, largest lists and libraries, access review links, and report coverage. |
| Taxonomy | Term groups, sets, terms, parent terms, IDs, and columns using a term set. |
| Search | Results across names, descriptions, columns, folders, pages, and terms, plus an empty-results state. |
| Downloads | Worksheet previews and sample Excel data dictionaries and permissions workbooks. |
| Print | Every collected section and expanded technical detail, regardless of the active tab or search. |
| Alternative states | A site member who cannot read permissions, an empty site, and missing site branding. |

### Working and simulated actions

The access summary distinguishes findings, completed checks with no findings, and unavailable checks.
It appears on the Permissions overview, with the separate-permission and missing-description findings.
The research example contains a guest and a link anyone can use.
The new-site example shows the no-guests message. The operations example shows unavailable permission checks.
Counts come from the selected example site's data and match the detail views.

The preview uses standard HTML tables with filtering and sorting. The production app retains its bundled Tabulator library.
Keeping Tabulator for interactive data tables is compatible with the proposed navigation and detail panels.
The printable report uses separate tables so it can include every row and expanded detail.

Navigation, search, site switching, description editing, sample Excel downloads, and printing work locally.
Description edits last only until you reload the page.
Use the pencil button or double-click the description to edit it in place.
Select **Save** or **Cancel**. You can also press Escape to cancel or Ctrl+Enter to save.
The pencil buttons work with a keyboard and have labels naming the description they edit.

The site-owner example supports the same description types as the current production app:
sites, lists and libraries, columns, taxonomy groups, term sets, and terms.
The site-member example is read-only. Real SharePoint and term-store permissions still need
to be enforced when this design is implemented in production.
Saved preview descriptions appear in search results where that field is searchable,
the data dictionary, and the full print report.

The footer links to the Eisenberg Family Depression Center, the source repository, and More Apps.
These are real website links; they do not run SharePoint actions.

Microsoft documents a page's thumbnail URL in the
[sitePage resource](https://learn.microsoft.com/en-us/graph/api/resources/sitepage?view=graph-rest-1.0).
The mockup uses a synthetic thumbnail and does not fetch a page image.
A thumbnail can be the page's selected image rather than a screenshot of its full contents.
Retrieval using this app's SharePoint session remains unverified; no Graph authentication or permissions were added.
The person access example accepts only `reader@example.org` and displays synthetic results.
It does not look up an account.

SharePoint actions show a dialog with the intended destination. They do not open or modify a real site.
The browser blocks external connections through the preview's Content Security Policy.
The preview does not store report data or preferences in browser storage.

The two workbooks contain the entire selected example site's data, regardless of filters.
The dictionary preserves the nine production sheets: Export_Info, Sources, Assets, Fields,
Value_Sets, Relationships, Dashboards, Visualizations, and Stewards.
The permissions workbook includes About, Permissions, Lists, Group_Members, Permission_Levels, and Site_Admins sheets.
Missing permission data stays marked as unavailable.
The worksheet headers are checked against the production export builders.
Examples with taxonomy include the production Term Store asset in the Assets sheet.
When a lookup target is absent from the collected example, the relationship is omitted.
The affected field's notes and Export_Info explain which lookup is unavailable.
These are synthetic examples, not changes to production workbook formats.
See the [functionality coverage audit](design-parity.md) for the full comparison and simulation boundaries.

### Printing

Select **Print full report / PDF** to inspect the full document.
Then select **Print / Save as PDF** to open the browser's print dialog.
The browser's own print command also uses the full report from any screen.

The print document is built from the example data, independently of visible tabs.
It includes site identity, every list and library, columns, top-level folders, permissions,
group members, sharing links, app access, taxonomy, pages, cleanup findings, and technical details.
It includes the individual access check only if you ran that example.
Otherwise, it says that no check has been run.

Report limitations remain visible. Item-level permissions and Microsoft 365 group members are not included.
Apps granted access through Microsoft Entra ID are outside the report.
No statement in the preview establishes that a site is secure.

### Verify and capture screens

The verification script uses the browser test dependencies already installed under `tests/node_modules`.
If those dependencies are missing, follow [Building and testing Sitenalyzer](development.md).
Run this command from the repository root:

```powershell
node mockups/site-brief/verify.cjs
```

The script checks navigation, keyboard focus in dialogs, input rejection, text-safe rendering,
site switching, Excel content, print coverage, and narrow layouts.
It checks dictionary keys for complete, limited, and empty examples and reopens every gallery link
in a fresh browser context. It also verifies the generated gallery's complete license header.
It scans the views with axe and writes screenshots, two synthetic workbooks, a tagged PDF,
a screen gallery, and a verification log under `mockups/site-brief/review/`.
The output contains only the synthetic examples.

### Accessibility scope

The preview uses semantic headings, navigation, tables, labeled controls, native dialogs,
visible keyboard focus, and layouts that reflow at 320 CSS pixels.
At narrow widths, selecting an item opens its details with a **Back to results** link.
Tables present each cell with its column label.

Automated checks and browser keyboard checks do not establish full accessibility.
A screen-reader review and testing inside the actual SharePoint web part remain necessary.
The PDF also needs a reading-order and tagging review in a PDF accessibility tool.

### Conclusion

Use the interactive preview and screen gallery to compare the proposed flows.
The production files under `src/` and `dist/` remain separate from this design preview.
